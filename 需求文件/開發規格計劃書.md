## 1. 產品願景與範圍

### 1.1 一句話
LifeOS 是一個**用自然語言操作的 AI 生活助理**：用講的（或 Siri）就能排程、記帳、管理健康/記憶/出行，並把重活交給 AI 與後端完成。

### 1.2 核心差異化
- **零學習成本**：全域自然語言輸入 + Siri，不必記功能在哪。
- **隱私優先**：敏感資料優先在裝置端處理；需上雲的明確告知與同意。
- **溫暖親切**：為一般人與長者設計（琥珀金、大字、問候、語音）。

### 1.3 功能全景
- **已有體驗（Demo 已示範）**：智慧排程、財務、健康管家、知識記憶庫、出行規劃、自動化、跨模組路由、新手指引、長照主題。
- **規劃新功能（會議提出，待正式開發）**：
  - 互動/成長層：F1 每日任務、F2 引導學習、F3 角色成長、F4 社交共同任務
  - 擴充：F5 郵件訂閱稽核、F6 運動身體評估
  - 後端驅動垂直功能：F7 趣味學習圖影、F8 穿搭換衣、F9 長照語音掛號

### 1.4 Demo 已驗證 vs 正式版要做
| 面向 | Demo 已驗證 | 正式版要做 |
|---|---|---|
| 體驗/UI | 七大功能頁、溫暖 UI、新手引導、長照主題 | 真實資料、無障礙、效能、上架打磨 |
| 裝置端 AI | 三級路由 + 降級（on-device/雲/規則式） | 真實模型額度、iOS 27 LanguageModel 正式化 |
| 後端 | 無（Demo 純裝置端） | 整套後端 Server（F4/F7/F8/F9）|
| 掛號/影像/社交 | 流程與契約設計 | 真實供應商/醫院/社交後端串接 |

## 2. 整體架構藍圖（所有角色對齊）

```
┌───────────────────────── 裝置端 App（前端工程師）─────────────────────────┐
│ SwiftUI 畫面 · 設計系統 · 新手指引/長照主題 · 全域輸入 · 七大功能頁         │
│ App Intents（Siri 入口）· LifeOSCloudKit（後端 client：逾時/重試/錯誤映射）│
└───────────────┬───────────────────────────────────────────────────────────┘
                │  Siri → App Intent → BackendClient（HTTPS + Sign in with Apple token）
┌───────────────▼───────────────── 後端 Server（後端工程師）──────────────────┐
│ 身分驗證 · API（intake/book…）· AI 編排 · job queue + APNs · 供應商抽象層   │
│  ├ F9 掛號：AI 解析 + 掛號資料源抽象層                                       │
│  ├ F7/F8：影像生成/編輯供應商（非同步 job）                                  │
│  └ F4：社交資料庫（好友/共同任務/排行榜）                                    │
└───────────────┬───────────────────────────────────────────────────────────┘
                │  雲端基礎設施（雲端架構師）
┌───────────────▼───────────────────────────────────────────────────────────┐
│ 部署/擴展/可用性 · APNs · Sign in with Apple · 機密管理 · 監控 · 資安合規   │
│ 外部 AI 供應商（LLM/影像）· 外部系統（掛號來源）                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

**同步 vs 非同步準則（跨角色契約）**
- **同步（≤3s，Siri/UI 即時回應）**：F9 掛號查詢、F4 任務狀態。
- **非同步（job + APNs 推播）**：F7/F8 影像生成等重運算。

## 3. 角色工作範圍與研究方向 ★本文件核心

### 3.1 前端工程師（iOS / SwiftUI）

**負責範圍**
- App 所有畫面與互動、SwiftUI 實作、設計系統落地。
- App Intents（Siri 語音入口）、與 LifeOSCloudKit 串接後端。
- 無障礙（VoiceOver / Dynamic Type / 長照可用性）、上架（隱私清單、entitlements）。

**Demo 可直接複用的資產**
- `LifeOSKit` 模組：DataKit、LLMCore（三級路由 + @Generable）、各功能 Kit、**DesignSystem**、**LifeOSCloudKit**（後端 client）。
- 設計系統：琥珀金主色、圓潤字體、新手指引（`OnboardingTracker`）、暖空狀態、成功慶祝 toast、**長照主題 `EldercareTheme` / `EldercareButton` / `SpeechReadout`**。
- 七大功能頁 + 全域輸入列 + 跨模組路由（`CrossModuleOrchestrator`）。
- `BackendClient`（逾時/重試/錯誤語意化、可注入 Transport，已有單元測試）。

**正式版要做 / 研究方向**
- 接上**真實後端**（取代 Demo 的純裝置端）；用 `BackendClient` 既有契約型別。
- **App Intents / Apple Intelligence 深化**：多輪語音對話、參數解析、`requestConfirmation`/`ProvidesDialog`（Demo 已有記帳/建事件範例可循）。
- 無障礙與長照可用性實測（長者實機測試）。
- 效能、離線、錯誤/載入狀態打磨；APNs 推播接收與長任務結果呈現（`JobStore`）。
- 上架：HealthKit/Siri/Push entitlements、PrivacyInfo.xcprivacy、Sign in with Apple 登入 UI。
- 研究：iOS 27 `LanguageModel` beta 正式化時程、StoreKit 2（若導入訂閱）。

### 3.2 後端工程師

**負責範圍**
- 後端 Server 與 API 實作、AI 編排（intake/book 等）、job queue + APNs、供應商/資料源抽象層、社交資料模型。

**從 Demo 接手的契約**
- LifeOSCloudKit 內的 API 型別即**前後端契約**：`AppointmentIntakeRequest/Response`、`AppointmentOption`、`AppointmentBookRequest/Response`、`BackendJob`。
- 後端 MUST 回傳符合這些型別的 JSON；契約變更需與前端同步。

**正式版要做 / 研究方向**
- **框架定案**（PO 建議 FastAPI，AI 生態成熟）+ 專案骨架、身分驗證（驗 Sign in with Apple identity → 簽自家 JWT）。
- **F9 intake AI**：LLM 供應商選型、prompt 設計、結構化輸出、**緊急症狀偵測**（回「建議就醫」不排程）。
- **掛號資料源抽象層**：先 mock；研究真實來源（健保快易通 / 醫院掛號 API / RPA）的可行性與優先序。
- **F7/F8**：影像生成/編輯供應商串接、非同步 job + APNs 回呼。
- **F4 社交**：好友/共同任務/排行榜資料模型與 API。
- **安全與合規**：JWT、速率限制、輸入驗證；醫療/個資**用後即刪、不訓練、稽核**。

### 3.3 雲端架構師

**負責範圍**
- 後端的部署架構、可擴展性、可用性、成本、資安、推播基礎設施、身分、資料治理、監控。

**要做 / 研究方向**
- **部署**：容器化、環境分離（dev/staging/prod）、編排（K8s / Serverless）選型。
- **推播與身分**：APNs 憑證與推播服務、Sign in with Apple 後端設定。
- **機密與資安**：供應商金鑰管理（KMS/Secrets）、TLS、WAF、速率限制。
- **資料治理/合規**：醫療與人物照「用後即刪」落地、加密、稽核日誌、個資法/醫療法遵。
- **成本/效能**：LLM 與影像生成 token 成本模型、用量監控與告警；**驗證 intake ≤3s 延遲預算在雲端的可行性**（區域、模型延遲）。
- **可靠性**：AI 供應商 fallback、可用性 SLA、災難復原。

## 6. F9 語音掛號：端到端範例（跨角色協作典範）

```
① 使用者：「嘿 Siri，我想要掛號」
② Siri → App Intent（前端：BookAppointmentIntent，自然語言參數）
③ App Intent → BackendClient.post(/appointment/intake)（前端→後端契約）
④ 後端（後端工程師）：AI 解析科別/症狀/偏好 → 查掛號資料源 → 回候選 + 待補欄位（同步 ≤3s）
⑤ Siri 語音互動（前端）：缺資訊追問；有方案則朗讀「找到◯醫院◯科◯醫師，最近可掛◯，要幫你掛嗎？」
⑥ 使用者確認 → requestConfirmation 通過
⑦ App Intent → /appointment/book（後端執行掛號）
⑧ 後端回結果 → Siri 語音回報 + 前端寫行事曆(SchedulerKit) + 回診提醒(AutomationKit)
```

**角色責任切分**
- **前端**：Intent 對話、語音朗讀（`SpeechReadout`）、長照 UI（`EldercareTheme`/大按鈕）、確認流程、跨模組收尾。
- **後端**：intake/book API、AI 解析、緊急症狀偵測、掛號資料源抽象層。
- **雲端架構師**：掛號來源串接的網路/安全、延遲預算、醫療資料合規與用後即刪。
- **PM**：契約凍結、整合測試、醫療法遵把關。

## 9. 驗收與 UX 完美準則（最高原則）

任何設計與實作，PO 的驗收基準是**使用者體驗必須完美**：
- **零空等**：同步 ≤3s，超過要有明確進行中回饋；重運算用 job + 推播。
- **語音優先 / 長者友善**：F9 全程語音 + 超大字 + 高對比 + 大按鈕。
- **錯誤溫和**：查無/失敗/斷線都要溫和明確、可重試、不遺失使用者輸入、不露技術錯誤碼。
- **隱私可信**：敏感資料優先裝置端；需上雲明確同意、用後即刪、不訓練。
- **醫療安全**：不診斷、只協助；疑似緊急狀況引導就醫。
- **一致性**：沿用既有設計系統（琥珀金/圓潤/問候/慶祝/長照主題）。

## 附錄 B：已知技術注意事項（接手必讀）
1. `@Generable` 巨集的 memberwise init 是 internal → 跨 module 建構需顯式 public init。
2. 中文數字單位字元（京/萬/四…）`Character.isNumber == true` → 數字掃描須限 `isASCII && isNumber`。
3. `.regularExpression` 在編譯模組行為不一致 → 解析改用手動字元掃描。
4. 新增 App/ 下檔案後須 `xcodegen generate` 才會被 build 看到。
5. 凡宣稱「完成」務必以實際 build / `swift test` / git log 查證（避免假性完成）。
