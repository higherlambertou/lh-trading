# 進場市場狀態紀錄 — 需求文件

> 給 Claude Code 實作參考
> 目標：每次進場（手動單與策略單都包含），把當下實際的決策依據（趨勢判斷、內外盤，以及 Hurst 等參考指標）與單筆資訊一起記錄，出場後回填損益，供日後驗證「自己的判斷與各項指標是否真的有用」
> 版本：2026-10-16 更新（納入以手動單為主的使用情境、內外盤、趨勢判斷標籤）

---

## 背景與動機

市場狀態面板（Hurst、IV）目前只作為顯示與人工參考，不參與任何下單決策。這個決定是對的：Hurst 在短樣本下估計誤差很大（面板上 60 根 K 棒的雜訊約 ±0.13），而且還沒有證據顯示「Hurst 判斷與策略類型相符時，績效比較好」。

**實際使用情況（使用者說明）**：多數進場是手動下單。手動單與策略單共用同一套風控（停利停損、口數限制、虧損上限）。手動下單時的主要依據是「趨勢」（使用者自行判斷）與「內外盤」（累計內外盤差與比），Hurst、IV 屬於輔助參考。

因此紀錄必須涵蓋實際的決策依據。只記 Hurst，會漏掉最重要的部分，日後無法檢驗。

要驗證這些東西有沒有用，需要資料：每一筆真實交易當下的狀態，與之後的損益。這些資料如果現在不記，之後就補不回來。

這份需求只做一件事：**多記幾個欄位，不改變任何交易行為。**

**刻意不做的事**：v1 不分析、不統計、不讓任何指標或標籤影響任何決策。先累積資料，等樣本足夠、且判斷標準事先決定之後，再另開需求。

> 註：這是工程需求整理，不是投資建議。

## v1 範圍

### 必做

1. **進場快照（手動單與策略單都要有）**
   - 每次進場成交時，寫入一筆紀錄，內容見「資料結構」
   - 以 `order_source` 區分 `manual` 與 `strategy`
   - 策略單：策略名稱與類型（趨勢 / 均值回歸 / 其他）由策略設定檔明確標示，程式不自行判斷
   - 手動單：策略名稱與類型為 `null`，不得報錯，也不得填入預設策略
   - 市場狀態欄位取「進場當下」已有的最新值，不重新計算、不補預設值

2. **內外盤快照**
   - 進場當下，記錄使用者在面板上看到的同一組數值：累計內盤量、累計外盤量、內外盤差、內外盤比
   - 必須同時記錄「累計起點」（屬於日盤或夜盤、何時重置），因為累計值依賴起點，不記就無法解讀
   - 資料來源與定義必須與面板一致，同一時刻兩邊的數字應相同

3. **趨勢判斷標籤（手動單，由使用者輸入）**
   - 趨勢是使用者自行判斷，程式算不出來，只能請使用者標記
   - 選項已確認：多 / 空 / 盤整 / 無明確判斷（最後一項避免進場時沒有看法卻被迫選一個，污染資料），另可選填一行備註
   - 順勢或逆勢不需另外輸入，分析時可由 `direction` 與 `trend_label` 推得
   - **輸入不得阻擋、延遲任何下單**：可在進場後補填
   - 記錄輸入時間 `label_entered_at`；若輸入時間晚於出場時間，標記 `label_after_exit = true`，因為已知結果後的標籤可能被事後記憶影響
   - 未填寫時，該欄位為 `null`，`missing_reason` 記 `not_entered`

4. **缺值處理**
   - 任何市場狀態或內外盤欄位取不到（例如 IV 層歷史資料未滿 60 天），該欄位記 `null`，並在 `missing_reason` 寫明原因
   - 不得用 0、上一次的值或預設值代替

5. **出場回填**
   - 出場後，以同一個 `trade_id` 回填：出場時間、出場價、損益（點數與 NTD）、出場原因
   - 出場原因至少區分：停損成交、停損未成交後市價接力、目標出場、手動出場、其他

6. **不影響交易**
   - 本功能不得改變任何進出場條件、口數或送單時機
   - 本文件新增的欄位（市場狀態、內外盤快照、趨勢標籤）只被寫入，不被任何策略或風控模組讀取作為決策輸入

7. **寫入失敗的處理**
   - 紀錄寫入失敗，不得阻擋下單（這是少數「失敗時照常動作」的地方，因為它只是觀察，不是風控）
   - 但失敗必須產生警示並留下記錄，不得靜默吞掉

8. **紀錄不可改寫**
   - 只新增，不修改歷史。需要修正時（包含補填或更改趨勢標籤），新增一筆更正紀錄並指向原紀錄

9. **可匯出**
   - 可匯出為 CSV，供之後在外部做分析，欄位完整、時區一致

### 選做（待使用者確認，見待確認事項 7）

- **「看到但沒做」的訊號紀錄**：手動情境下，使用者本來會進場卻跳過或縮量，可用最低成本的方式記一筆（例如一鍵按鈕加時間）。這能補上選擇偏差，但不是 v1 必要

### 不做（v1）

- 任何統計、圖表或分析頁面
- 讓 Hurst、IV、內外盤或趨勢標籤影響進場、口數或策略開關
- 回補歷史交易的市場狀態（無法確定當時的值就不補）
- 記錄 MAE / MFE（持倉期間最大不利與有利變動），見待確認事項

## 資料結構（示意，欄位名稱由實作決定）

```
trade_id            唯一識別，進出場共用
order_source        manual | strategy
strategy_name       策略名稱；手動單為 null
strategy_type       trend | mean_reversion | other；手動單為 null
direction           long | short
entry_time          統一時區（建議 Asia/Taipei）
entry_price
stop_price
lots

subjective:         （手動單；策略單為 null）
  trend_label       multi | short | range | none（多 / 空 / 盤整 / 無明確判斷）
  note              選填
  label_entered_at  輸入時間
  label_after_exit  輸入時間晚於出場時間時為 true
  missing_reason    欄位為 null 時的原因（例如 not_entered）

order_flow:         內外盤快照
  inside_volume     累計內盤量
  outside_volume    累計外盤量
  net_diff          外盤 − 內盤
  ratio             內外盤比（定義與面板一致）
  accum_start       累計起點（日盤或夜盤、重置時間）
  source            資料來源
  state_timestamp   該值的計算時間
  missing_reason

market_state:
  hurst_value       例：0.36
  hurst_window      例：60（根）
  hurst_bar_period  例：1 分 K
  hurst_noise       面板上顯示的誤差估計，例：0.132
  iv_value          可為 null
  state_timestamp   該值的計算時間，用來檢查是否過期
  missing_reason    欄位為 null 時的原因

exit_time           出場後回填
exit_price
pnl_points
pnl_ntd
exit_reason
```

以上數值僅為示意。

## 驗收標準

1. 每一筆進場成交，都有且僅有一筆進場快照；手動單與策略單的 `order_source` 都正確
2. 手動單的策略名稱與類型為 `null`，流程不報錯
3. 內外盤快照與面板在同一時刻顯示的數值相同（同一來源、同一定義）；`accum_start` 有記錄；測試涵蓋日盤與夜盤交界、重置之後的第一筆
4. 市場狀態或內外盤欄位取不到時，該欄位為 `null` 且 `missing_reason` 有值；不存在以 0 或預設值代替的情況
5. 趨勢標籤沒有輸入時，下單照常進行，快照中該欄位為 `null` 且原因為 `not_entered`（需有測試）
6. 趨勢標籤的輸入時間被記錄；輸入時間晚於出場時間時，`label_after_exit` 為 true
7. 出場後，同一 `trade_id` 的損益與出場原因被回填；損益可用進出場價與口數手算驗證
8. 本功能啟用前後，同一組行情重播下，送出的訂單完全相同（需有測試）
9. 程式碼檢查或測試能證明：沒有任何策略或風控模組讀取 `market_state`、`order_flow`、`subjective` 欄位
10. 紀錄寫入失敗時，下單照常進行，並產生警示與錯誤記錄
11. 程式重啟或重複觸發時，不重複寫入同一筆進場，也不遺失（以 `trade_id` 保證冪等）
12. 可匯出 CSV，欄位完整、時區一致
13. 單元測試涵蓋：市場狀態缺值、IV 歷史不足、內外盤缺值、日夜盤交界、手動單與策略單、標籤未填與延後填寫、部分成交、停損未成交後接力出場、重複事件

## 待確認事項

1. **策略類型標籤**：策略單才需要。目前有哪幾個策略、各自算趨勢型還是均值回歸型，需要使用者定義。有些策略可能兩者都不是，標 `other`
2. **儲存位置**：沿用現有交易紀錄的儲存方式，還是另開一張表？建議沿用，避免兩邊對不上
3. **Hurst 的計算窗口與週期**：以面板目前的設定為準，還是進場策略自己使用的週期？兩者不同時，建議兩個都記
4. **部分成交與多次成交**：以「一筆交易」為單位，還是以每次成交為單位？建議以交易為單位，成交明細另存
5. **MAE / MFE**：若日後想分析「持倉期間最大不利變動」，現在不記就補不回來。要不要納入 v1？
6. **是否記錄出場當下的市場狀態**：能看出行情在持倉期間是否改變，但欄位會多一倍。建議先不記
7. **未進場的訊號**：被風控拒絕、條件觸發但未成交，或手動情境下「看到但沒做」的訊號，要不要也記？這會影響日後判斷有沒有選擇偏差
8. **內外盤的累計規則**：已確認，日盤與夜盤各自重置。仍待實作時確認的是資料來源（券商 API 提供的成交內外盤標記，或自行計算），以官方文件為準，並且要與面板完全一致。無法判定方向的成交怎麼處理，也要與面板相同
9. **是否同時記短窗口版本**：使用者目前看的是累計值，累計值越到後面越不敏感。若想日後比較「累計」與「最近 N 分鐘」哪個更有用，現在不記就補不回來。建議列為選做，由使用者決定
10. **趨勢標籤的輸入時機與客觀對照**：選項已確認（見必做 3）；待定的是進場後多久內補填。另可考慮同時自動記一個客觀的趨勢代理值（例如價格相對某均線的位置）作對照，日後可比較「使用者判斷」與「規則版」，但不是必要
11. **多少筆之後才做判斷**：樣本門檻與判斷標準，建議在開始分析之前由使用者事先決定並寫下，不要看到結果之後再調整
12. **前提風險**：
    - Hurst 在短窗口下誤差大，早期樣本可能無法得出結論
    - 手動單中，使用者的判斷與各項指標是混在一起的，資料只能描述「在某種標籤與某種內外盤組合下，績效如何」，無法單獨證明哪一項有用
    - 主觀標籤容易被事後結果影響，應以 `label_entered_at` 與 `label_after_exit` 來判斷可信度
    - 以上都是預期內的限制，不是實作缺陷

## 與其他文件的關聯

- 「部位大小控管（固定風險）」：決策紀錄可共用 `trade_id`，之後能把口數決策與市場狀態對照
- 「盤前跨市場資訊紀錄與驗證」：可用交易日把當日盤前快照與進場快照連起來，一併分析
- 市場狀態層（Hurst、IV）：本文件是它「從顯示走向驗證」的第一步，在驗證完成之前維持僅供參考
