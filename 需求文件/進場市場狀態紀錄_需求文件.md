# 進場市場狀態紀錄 — 需求文件

> 給 Claude Code 實作參考
> 目標：每次進場時，把當下的市場狀態（Hurst 等）與策略資訊一起記錄，出場後回填損益，供日後驗證「市場狀態指標是否真的有用」

---

## 背景與動機

市場狀態面板（Hurst、IV）目前只作為顯示與人工參考，不參與任何下單決策。這個決定是對的：Hurst 在短樣本下估計誤差很大（面板上 60 根 K 棒的雜訊約 ±0.13），而且還沒有證據顯示「Hurst 判斷與策略類型相符時，績效比較好」。

要驗證這件事，需要資料：每一筆真實交易當下的市場狀態，與之後的損益。這些資料如果現在不記，之後就補不回來。

這份需求只做一件事：**多記幾個欄位，不改變任何交易行為。**

**刻意不做的事**：v1 不分析、不統計、不讓 Hurst 或 IV 影響任何決策。先累積資料，等樣本足夠、且判斷標準事先決定之後，再另開需求。

> 註：這是工程需求整理，不是投資建議。

---

## v1 範圍

### 必做

1. **進場快照**
   - 每次進場成交時，寫入一筆紀錄，內容見「資料結構」
   - 策略類型（趨勢 / 均值回歸 / 其他）由策略設定檔明確標示，程式不自行判斷
   - 市場狀態欄位取「進場當下」已有的最新值，不重新計算、不補預設值

2. **缺值處理**
   - 任何市場狀態欄位取不到（例如 IV 層歷史資料未滿 60 天），該欄位記 `null`，並在 `missing_reason` 寫明原因
   - 不得用 0、上一次的值或預設值代替

3. **出場回填**
   - 出場後，以同一個 `trade_id` 回填：出場時間、出場價、損益（點數與 NTD）、出場原因
   - 出場原因至少區分：停損成交、停損未成交後市價接力、目標出場、手動出場、其他

4. **不影響交易**
   - 本功能不得改變任何進出場條件、口數或送單時機
   - 市場狀態欄位只被寫入，不被任何策略或風控模組讀取作為決策輸入

5. **寫入失敗的處理**
   - 紀錄寫入失敗，不得阻擋下單（這是少數「失敗時照常動作」的地方，因為它只是觀察，不是風控）
   - 但失敗必須產生警示並留下記錄，不得靜默吞掉

6. **紀錄不可改寫**
   - 只新增，不修改歷史。需要修正時，新增一筆更正紀錄並指向原紀錄

7. **可匯出**
   - 可匯出為 CSV，供之後在外部做分析

### 不做（v1）

- 任何統計、圖表或分析頁面
- 讓 Hurst、IV 影響進場、口數或策略開關
- 回補歷史交易的市場狀態（無法確定當時的值就不補）
- 記錄 MAE / MFE（持倉期間最大不利與有利變動），見待確認事項

## 資料結構（示意，欄位名稱由實作決定）

```
trade_id            唯一識別，進出場共用
strategy_name       策略名稱
strategy_type       trend | mean_reversion | other   （來自設定，不由程式判斷）
direction           long | short
entry_time          統一時區（建議 Asia/Taipei）
entry_price
stop_price
lots
market_state:
  hurst_value       例：0.36
  hurst_window      例：60（根）
  hurst_bar_period  例：1 分 K
  hurst_noise       面板上顯示的誤差估計，例：0.132
  iv_value          可為 null
  state_timestamp   該值的計算時間，用來檢查是否過期
  missing_reason    欄位為 null 時的原因
exit_time           出場後回填
exit_price
pnl_points
pnl_ntd
exit_reason
```

以上數值僅為示意。

## 驗收標準

1. 每一筆進場成交，都有且僅有一筆進場快照
2. 市場狀態欄位取不到時，該欄位為 `null` 且 `missing_reason` 有值；不存在以 0 或預設值代替的情況
3. 出場後，同一 `trade_id` 的損益與出場原因被回填；損益可用進出場價與口數手算驗證
4. 本功能啟用前後，同一組行情重播下，送出的訂單完全相同（需有測試）
5. 程式碼檢查或測試能證明：沒有任何策略或風控模組讀取 `market_state` 欄位
6. 紀錄寫入失敗時，下單照常進行，並產生警示與錯誤記錄
7. 程式重啟或重複觸發時，不重複寫入同一筆進場，也不遺失（以 `trade_id` 保證冪等）
8. 可匯出 CSV，欄位完整、時區一致
9. 單元測試涵蓋：市場狀態缺值、IV 歷史不足、部分成交、停損未成交後接力出場、重複事件

## 待確認事項

1. **策略類型標籤**：目前有哪幾個策略、各自算趨勢型還是均值回歸型，需要使用者定義。有些策略可能兩者都不是，標 `other`
2. **儲存位置**：沿用現有交易紀錄的儲存方式，還是另開一張表？建議沿用，避免兩邊對不上
3. **Hurst 的計算窗口與週期**：以面板目前的設定為準，還是進場策略自己使用的週期？兩者不同時，建議兩個都記
4. **部分成交與多次成交**：以「一筆交易」為單位，還是以每次成交為單位？建議以交易為單位，成交明細另存
5. **MAE / MFE**：若日後想分析「持倉期間最大不利變動」，現在不記就補不回來。要不要納入 v1？
6. **是否記錄出場當下的市場狀態**：能看出行情型態在持倉期間是否改變，但欄位會多一倍。建議先不記
7. **未進場的訊號**：被風控拒絕、或條件觸發但未成交的訊號要不要也記？這會影響日後判斷有沒有選擇偏差，但不是 v1 必要
8. **多少筆之後才做判斷**：樣本門檻與判斷標準，建議在開始分析之前由使用者事先決定並寫下，不要看到結果之後再調整
9. **前提風險**：Hurst 在短窗口下誤差大，即使記錄下來，早期樣本也可能無法得出結論；這是預期內的事，不是實作缺陷
