# 門檻判斷連續化檢查 — 需求文件

> 給 Claude Code 實作參考
> 目標：找出現有系統裡「用硬門檻切割模糊/連續指標」的地方，評估改成連續權重的可行性

---

## 背景與動機

現有交易系統裡，多個市場狀態判斷都是用「硬門檻」做二元分類，例如：

- Hurst 指數 > 0.55 算「趨勢延續」，< 0.55 不算
- IV 百分位超過某個值算「市場緊張」
- 外/內盤比例超過某個值算「買方主動」

這類判斷方式有個結構性問題：**門檻附近的兩個數值（例如 0.549 跟 0.551），代表的市場狀態幾乎沒有本質差別，但系統會給出截然相反的分類結果。** 如果指標在門檻附近反覆震盪（這在真實市場噪音下很常見），系統會不斷切換判定結果，造成不必要的訊號反轉跟交易成本。

這個問題不限於單一指標，現有系統裡用門檻判斷的地方，可能普遍存在這個風險，目前沒有逐一檢查過。

---

## 需要做的事

### 第一步：盤點

列出現有系統（8個策略 + Hurst/IV/外內盤比例等市場狀態判斷）裡，所有用「硬門檻」做二元或多元分類的地方，整理成一份清單（參數名稱、門檻值、用在哪個策略/判斷邏輯）。

### 第二步：檢查門檻附近的「邊界震盪」風險

針對清單裡的每個門檻，用歷史資料檢查：該指標在這個門檻值附近，震盪穿越門檻的頻率有多高。頻率越高，代表這個門檻越容易造成不必要的訊號反轉。

### 第三步：評估改成連續權重的可行性

針對震盪風險較高的項目，評估是否能把「二元判斷（是/不是趨勢）」改成「連續權重（趨勢確信度隨指標數值連續變化，用來調整部位大小、停損鬆緊，而不是切換開關）」。

這個方向跟之前「市場指標視覺化工具」需求文件裡的設計精神一致——視覺化工具用的是顏色漸變（連續），而不是二元分類，兩者可以互相參照。

---

## 技術實作建議（供 Claude Code 評估）

- 盤點工作可以先從程式碼裡搜尋所有的門檻比較邏輯（if 判斷、閾值常數）開始
- 「邊界震盪頻率」可以用歷史資料，計算指標在門檻 ±N% 範圍內的穿越次數
- 連續權重化不需要一次全部改完，建議先挑震盪風險最高的 1-2 個項目做驗證，確認方向有效再擴大

---

## 待確認事項

- 現有系統裡所有用到門檻判斷的具體位置，需要先盤點才能確認完整清單
- 改成連續權重後，策略邏輯（比如 scalp 的狀態機）要怎麼配合調整，需要進一步討論
