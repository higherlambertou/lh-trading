# 停損機制極端行情驗證 — 需求文件

> 給 Claude Code 實作參考
> 目標：把現有停損設定從「主觀風險胃納決定」，驗證/校正成「統計數據支撐」

---

## 背景與動機

現有停損幅度的設定邏輯是：「我自己覺得單次交易能接受的最大虧損是多少」，直接拿這個金額/點數去設停損。

這個設定方式有兩個沒被驗證過的風險：

1. **正常波動下，這個幅度會不會太窄，導致常被雜訊洗出場**（方向判斷對了，但被正常市場震盪掃到停損出場）
2. **極端行情（跳空、流動性枯竭）下，這個幅度的保護力有多少**——現有停損機制是「限價單，若未成交則轉市價單」，但轉換前的等待時間窗口，恰好是行情劇烈跳動時滑價最大的時刻，實際成交價可能遠差於設定的停損點

目前完全沒有拿歷史數據驗證過上述兩點，風控信心建立在「機制存在」而非「機制的實際表現」上。

---

## 需要驗證的兩件事

### 驗證一：正常波動下的停損合理性

用歷史 ATR（或其他波動率指標）資料，檢查現有停損幅度：

- 對應到歷史上大約百分之多少的「正常波動」會觸發停損
- 如果停損幅度明顯小於正常波動範圍，代表可能常態性地被雜訊洗出場（勝率受雜訊干擾，不是方向判斷錯誤）

### 驗證二：極端行情下的實際滑價

找出歷史上幾次有紀錄的極端跳空/流動性枯竭事件（例如台指期曾經出現的急跌急漲時段），回測：

- 現有「限價轉市價」機制的等待時間窗口內，價格實際跳動了多少
- 如果當時用現有停損設定，實際成交價會跟設定的停損點差多少（實際滑價估算）

---

## 技術實作建議（供 Claude Code 評估）

- 需要台指期的歷史 tick 或分鐘級資料，覆蓋至少幾次公認的極端行情時段
- ATR 計算可沿用現有邏輯（orb、vwap_revert 策略已有 ATR 追蹤停損的實作，可參考）
- 「限價轉市價」的等待時間窗口長度（目前設定值）需要先確認，再去回測那段時間內的實際價格跳動
- 建議輸出：一份對照表，列出「現有停損幅度」在（a）正常波動下的觸發頻率、（b）極端行情下的實際滑價估算，兩種情境下的表現

---

## 待確認事項

- 現有「限價轉市價」的等待時間窗口，目前設定是多少秒/分鐘
- 歷史上要挑哪幾次具體的極端行情事件作為驗證樣本
- 驗證結果如果顯示現有停損幅度不合理，下一步要怎麼調整（可能跟之前那份視覺化工具文件裡的動態停損需求可以合併討論）
