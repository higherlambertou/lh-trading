# 部位大小控管（固定風險）— 需求文件

> 給 Claude Code 實作參考
> 目標：把目前「固定口數」進場，改成「依單筆風險計算口數」，並在策略之外加一層獨立的風控層，限制整體曝險

---

## 背景與動機

現況是每次進場使用固定口數，系統已在正式盤運行。固定口數有三個問題：

1. **每筆實際風險不一致**：停損距離不同，同樣口數的實際虧損差很多
2. **沒有人看到全貌**：多個策略各自進場，各自看起來合理，但加總的風險沒有被任何一處檢查
3. **風險上限寫在策略裡，容易被改動或繞過**

這份需求要做的是：由獨立的風控層決定口數，策略只能提出「想進場、停損在哪裡」。

**刻意不做的事**：v1 不用 Kelly 公式直接計算部位。Kelly 需要可靠的勝率與賠率，目前累積的真實交易樣本還少，估計誤差會被放大。v1 使用固定的、保守的單筆風險比例，等有足夠樣本後再重新檢視。

> 註：這是工程需求整理，不是投資建議。所有風險參數由使用者自行決定。

## v1 範圍

### 必做

1. **口數計算（純函式）**
   - 公式：`口數 = floor(帳戶權益 × 單筆風險比例 ÷ (停損點數 × 每點價值))`
   - 輸入：帳戶權益、單筆風險比例、停損點數、每點價值、各項上限
   - 輸出：最終口數，以及計算過程（每個步驟的中間值、哪個上限生效）
   - 計算結果 < 1 口時：預設**不進場**並記錄原因，不要自動補到 1 口（見待確認事項 1）

2. **多層上限（取其中最小值）**
   - 單筆口數上限（每個策略可各自設定）
   - 保證金使用率上限（全帳戶）
   - 總風險上限：所有未平倉部位「到停損的風險」加總，不得超過帳戶權益的某個比例
   - 單日最大虧損：觸發後停止開新倉，已有部位的停損與平倉照常運作

3. **失效時保守處理（fail closed）**
   - 帳戶權益取不到、已過期、或數值異常 → 不進場，寫入紀錄
   - 策略沒有提供停損，或停損點數 ≤ 0 → 不進場
   - 任何一個輸入無法確認時，預設結果是「不下單」，不是「用預設值下單」

4. **獨立風控層**
   - 位置在「策略」與「下單」之間，是獨立模組
   - 策略只能提交：方向、進場意圖、停損價位
   - **口數由風控層決定**，風控層不採信策略傳來的口數
   - 策略不得有繞過風控層直接下單的路徑

5. **紀錄**
   - 每次決策記錄：輸入值、計算結果、哪一個上限生效、最終送出的口數、被拒絕的原因
   - 目的是日後能用這些紀錄做事後檢討，而不是只留下結果

6. **設定檔**
   - 風險比例與各項上限放在設定檔，不寫死在程式或策略中
   - 修改時要留下紀錄（時間、舊值、新值、理由）
   - 執行中不允許由策略修改

7. **影子模式（上線前）**
   - 新口數計算先「並排運行」，只記錄、不實際下單，與目前固定口數對照
   - 觀察一段時間，確認計算結果合理再切換

### 不做（v1）

- Kelly 公式自動計算或自動調整風險比例
- 依 Hurst、IV 等市場狀態動態調整風險比例
- 加碼、減碼或移動停損邏輯
- 依資金曲線自動調整
- 跨商品的相關性模型

## 參數（示意，由使用者決定）

| 參數 | 說明 | 示意值 |
|---|---|---|
| 單筆風險比例 | 每筆交易願意虧損的帳戶權益比例 | 偏保守起步，例如 0.25%–0.5% |
| 單筆口數上限 | 每個策略各自設定 | 待定 |
| 保證金使用率上限 | 全帳戶 | 待定 |
| 總風險上限 | 所有未平倉部位到停損的風險加總 | 待定 |
| 單日最大虧損 | 觸發後停止開新倉 | 待定 |

以上示意值僅用於說明，不構成建議。

## 驗收標準

1. 口數計算與手算一致。範例（數字為示意）：
   - 權益 100 萬、單筆風險 0.5%（即 5,000 元）、微台、停損 50 點 → 5,000 ÷ (50 × 10) = **10 口**
   - 同條件但停損 400 點、大台 → 5,000 ÷ (400 × 200) = 0.06 → **0 口，不進場**
2. 任何上限被觸發時，口數取最小值，並在紀錄中標明是哪一個上限生效
3. 權益缺失、過期或異常，一律不進場
4. 策略沒有任何路徑可以繞過風控層直接下單（需有測試或程式碼層面的檢查）
5. 單日最大虧損觸發後，不再開新倉；已有部位的停損與平倉仍正常運作
6. 影子模式期間，新舊口數的差異可由紀錄查到
7. 設定的每一次修改都有紀錄
8. 單元測試涵蓋：停損為 0、權益為 0 或負值、算出小於 1 口、極大停損、各上限的優先順序、fail-closed 行為

## 待確認事項

1. **算出小於 1 口時**：不進場（建議），還是進 1 口（此時實際風險會超過設定的比例）？
2. **多策略同時進場時**，總風險上限怎麼分配：平均分、先到先得，還是依策略設定各自的預算？
3. **滑價與跳空**：風險是用「到停損的距離」估算的，但停損可能成交在更差的價位。要不要加一個緩衝（例如停損距離乘上係數，或固定加幾點）？
4. **帳戶權益的定義**：用權益數，還是可動用保證金？
5. **單日最大虧損的計算範圍**：日盤與夜盤分開，還是以一個交易日合計？
6. **停損觸發卻未成交的情況**：目前限價停損單若沒成交，後續的市價接力單是由主程式送出，程式不在就不會送出。總風險上限的計算**假設停損會成交**，這個假設在極端行情下不一定成立，會低估實際風險。這件事需要另一份需求處理（災難停損與獨立看門狗），不在本文件範圍內，但請實作時留意這個前提。
