# 市場指標視覺化工具 — 需求文件

> 給 Claude Code 實作參考
> 目標:把現有的三個交易判斷指標,轉換成直覺的視覺化呈現,取代直接看數字判讀

---

## 背景與動機

現有的市場狀態判斷系統用三個指標:
- Hurst 指數(趨勢延續 vs 均值回歸)
- IV 百分位(市場緊張/波動程度)
- 外/內盤比例(即時買賣方力道)

目前是分別看三個數字做判斷。靈感來自一款邏輯解謎遊戲(N×N 格子,每格有顏色和圖案,規則是每行每列只能有一個特定顏色/圖案,且不能相連)——這款遊戲用「顏色+位置+形狀」同時編碼多個約束條件,一眼掃過去就能判斷規則有沒有被滿足。

**核心設計原理**:人類視覺系統能在「有意識思考之前」快速處理顏色、形狀、位置這類視覺特徵(預先注意處理,preattentive processing),比逐一讀取數字更快判斷出「協調」或「矛盾」的狀態。

---

## 設計目標

不是做遊戲,是做一個**輔助決策的視覺化面板**。目標:
1. 一眼判斷當前三個指標各自的狀態
2. 一眼判斷三個指標之間是否「協調」或「互相矛盾」(矛盾可能代表不宜進場)
3. 取代逐一讀數字、心算判斷的過程

---

## 具體視覺化設計方案(初版,可調整)

### 維度一:Hurst 指數 → 顏色色相(Hue)

```
Hurst > 0.55(趨勢延續)   → 暖色系(紅、橙)
Hurst < 0.45(均值回歸)   → 冷色系(藍、綠)
0.45-0.55(中性)         → 灰色/白色
```

### 維度二:IV 百分位 → 顏色飽和度/亮度(Saturation/Brightness)

```
IV 百分位越高(市場越緊張,接近臨界點) → 顏色越飽和、越鮮豔
IV 百分位越低                        → 顏色越淡、接近灰階
```

### 維度三:外/內盤比例 → 獨立形狀符號(疊加在色塊上)

```
外盤 > 內盤(買方主動) → 向上箭頭或圓點
內盤 > 外盤(賣方主動) → 向下箭頭或方塊
```

### 判讀邏輯範例

```
鮮豔紅色區塊 + 向上箭頭
= 強烈趨勢延續 + 市場緊張 + 買方主動
= 三指標協調,趨勢訊號較可信

暖色(趨勢延續)+ 向下箭頭(賣方主動)
= 視覺上「不協調」
= 指標之間可能矛盾,考慮觀望
```

**核心價值**:視覺上的「協調感」或「衝突感」,可能直接對應到指標間是否存在有意義的相關性或矛盾,不需要另外計算統計相關係數才能感知。

## 重要限制與驗證要求(必須執行,不可省略)

**這是最關鍵的一步,設計配色方案本身容易產生「看起來很有洞察力但實際上只是好看」的陷阱。**

在把這套視覺化系統用於實際即時判斷之前,必須:

1. 用歷史數據回放測試,記錄「視覺上顯得協調/矛盾」的時間點
2. 對照這些時間點,用 CUSUM 或既有的統計驗證框架,檢查「視覺上感覺對的時候」跟「事後驗證訊號準不準」是否真的對得上
3. 如果視覺上「感覺對」但統計上沒有對應的顯著性,代表這套設計只是美觀,不是有效訊號,需要重新調整配色/符號的映射邏輯

**不能跳過這一步,直接憑感覺上線使用。**

## 資料來源(對照現有系統)

- Hurst 指數:可沿用 `hurst_analyzer.py` 的滾動計算邏輯
- 外/內盤比例:`scalp` 策略中已有相同概念的實作(momentum_window / momentum_threshold 參數),可直接複用其計算方式,詳見 STRATEGIES.md
- IV 百分位:需確認目前資料來源(選擇權報價或既有選擇權波段策略的計算方式)

## 技術實作建議(供 Claude Code 評估)

- 即時更新的效能問題(如果要即時呈現,需考慮更新頻率與渲染成本)
- 圖表庫選型(依實際技術棧決定)
- 建議先做「歷史數據回放模式」作為第一版,驗證視覺化邏輯有效後,再做即時模式
- 三個維度的映射參數(顏色門檻值、飽和度曲線)應該做成可調整的設定,方便後續根據驗證結果微調

## 待確認事項(開發前可能需要進一步討論)

- 具體的顏色數值(色相角度、飽和度區間)尚未定案,可在實作時一併討論
- 是否需要一個「總覽儀表板」同時顯示多個時間週期,或先聚焦單一時間週期
- 形狀符號的視覺大小、是否需要動畫效果表示變化趨勢
